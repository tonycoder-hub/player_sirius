# Player Sirius 待决策记录

这个文件只记录需要产品/API 选择的问题。修 bug 时先按保守方案推进，不因为这些问题中断。

## 手机和虚拟机上的扫描播放列表

- 状态：需要产品决策。
- 背景：HarmonyOS picker 暴露了 `DocumentSelectOptions.selectMode = DocumentSelectMode.FOLDER`，但当前 DevEco SDK 注释标明 folder 模式只支持 2-in-1 设备。手机和多数虚拟机配置里，系统 picker 可能根本不能选中文件夹。
- 当前实现：把移动端主路径命名为“扫描播放列表”。用户可以选择多个视频，应用会导入可读视频并提示未导入成功的文件与原因；真正的“选文件夹”入口保留给系统支持的设备。
- 已定方向：移动端不强求完整目录扫描；扫描播放列表可以只导入用户选中的一批文件，但必须清楚传递成功和失败明细。

## 鸿蒙系统流转 vs DLNA 扩展

- 状态：需要 API 和交互决策。
- 背景：普通用户应优先使用鸿蒙系统自身支持的流转/投播/接续能力；DLNA/UPnP 适合作为兼容电视、盒子、旧渲染器的单独扩展。
- 当前实现：网络页入口已经改成“鸿蒙流转 / DLNA”，现有 DLNA 面板继续作为扩展入口。
- 待决策：优先接入哪一个鸿蒙系统能力；投播时传当前网络 URL、本地 HTTP 代理 URL，还是基于系统媒体会话。

## DLNA 搜索可靠性

- 状态：可继续实现，不阻塞主链路。
- 背景：DLNA 搜索依赖组播、同网段、路由器设置、设备兼容性和权限；搜索为空可能是没有设备，也可能是 Wi-Fi 隔离或 SSDP 处理不完整。
- 当前目标：把 DLNA 明确做成高级扩展，展示更清晰的搜索状态，不把它当作唯一投播路径。
- 待决策：后续用哪些设备做验证矩阵，例如鸿蒙 TV、Android TV、Windows Renderer、VLC Renderer、NAS Renderer。

## 字幕和音轨

- 状态：已实现第一版，等待真机/样片验证。
- 背景：外挂字幕目前由应用层 overlay 渲染；内嵌音轨切换依赖 AVPlayer，并且只能在 player prepared 之后调用。
- 当前实现：打开视频时先扫描同目录 `.srt`，用视频名和字幕名的最长公共子序列自动选择默认字幕；匹配不到再用已记住的字幕，最后才手选。字幕 URI 和偏移会按视频记忆。
- 待验证：不同 picker URI 是否允许列同目录；不能列目录时会走记忆/手选兜底。

## 播放控制和横竖屏

- 状态：已做第二版，等待 UX 验证。
- 背景：播放画面已经加上基础 overlay 控件；横屏下按返回会先切回竖屏，再允许离开页面。
- 当前实现：控制条精简到进度、上一项、播放/暂停、下一项和横竖屏；单击播放/暂停，长按打开字幕/音轨，横滑快进/快退，左侧竖滑亮度，右侧竖滑音量。
- 待验证：控制条是否需要自动隐藏，以及哪些 VLC 风格操作继续下沉到底部面板。
